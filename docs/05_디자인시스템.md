## 0. 개요

### 0.1 디자인 방향

대형 가전 브랜드의 웹사이트와 멤버십 앱에서 느껴지는 **"깨끗하고 믿음직한" 분위기**를 모티브로 하되, 시각 요소는 모두 독자적으로 정의했습니다.

| 키워드 | 적용 방식 |
|---|---|
| 화이트 기반 | 배경은 순백(`#FFFFFF`), 섹션 구분은 아주 옅은 쿨 그레이(`gray-50`) 면으로. 테두리·그림자는 최소화 |
| 절제된 블루 포인트 | 블루(`blue-600 #1F5BD6`)는 **주 CTA, 선택 상태, 링크, 진행률**에만. 한 화면의 블루 면적은 10% 이하 |
| 둥근 버튼 | 모든 버튼·칩·배지는 알약형(`radius-full`). 카드는 20px, 모달·바텀시트는 28px |
| 넉넉한 여백 | 4px 그리드, 섹션 간 40~72px, 카드 내부 20~24px. 고객 화면은 "한 화면 한 메시지" |
| 단정한 타이포 | Pretendard, 제목 자간 -2%, 굵기는 400/600/700 세 가지 위주 |

### 0.2 사용하지 않는 것 (지식재산 보호)

- 특정 기업의 **로고, 상표, 워드마크, 슬로건**
- 특정 기업 **전용 폰트**(예: SamsungOne, SamsungSharpSans) → 무료 폰트 **Pretendard**(SIL OFL 1.1)로 대체
- 특정 기업의 **고유 아이콘·일러스트·사진·브랜드 컬러 코드 그대로**: 블루 계열도 독자 값으로 새로 정의
- 미리보기의 아이콘은 이 문서용 임시 라인 아이콘입니다. 실제 앱에서는 오픈소스 아이콘 세트(예: Lucide, Tabler Icons, MIT 라이선스) 중 하나로 통일하세요.

### 0.3 채널별 밀도

같은 토큰을 쓰되, `<html data-channel="...">` 속성 하나로 컨트롤 크기와 글자 크기를 바꿉니다.

| 채널 | `data-channel` | 기준 화면 | 특징 |
|---|---|---|---|
| 고객 앱 (C) | `customer` (기본) | 375 모바일 → 반응형 웹 | 여백 넓게, 큰 CTA 하나, 친절한 문장형 문구 |
| 기사 앱 (T) | `tech` | 375 모바일 | **최소 터치 48dp**(03_IA §6.2), 본문 16px, 버튼 52~64px. 장갑·햇빛 아래 사용 고려 |
| 관리자 웹 (A) | `admin` | 1440 PC | 정보 밀도 우선. 입력·버튼 36px, 본문 14px, 카드 반경 12px |

### 1.3 색 사용 규칙

1. **Primary 버튼은 화면당 1개.** 나머지는 secondary/outline/ghost.
2. 블루는 "누를 수 있음/선택됨"의 신호로만. 장식용 블루 면적 금지.
3. 강조가 필요하지만 블루가 과할 때(기사 앱 "출발하기", 필터 칩 선택)는 **다크(gray-900)** 를 씁니다.
4. 텍스트 대비 WCAG AA(4.5:1) 이상. `gray-400`은 플레이스홀더·비활성 전용.
5. 다크 모드는 v1 범위 밖. 의미 색상 토큰만 재매핑하면 되도록 구조를 잡아 두었습니다.

## 2. 주문 상태 배지 (03_IA §6.1 반영)

같은 상태 코드는 3채널 모두 **같은 색**. 표시명만 채널에 따라 다릅니다. 색만으로 구분하지 않도록 항상 텍스트(+점)를 함께 표시합니다.

| 상태 코드 | 고객 표시명 | 기사·관리자 표시명 | 색 | 전경 / 배경 | 대비 | 클래스 |
|---|---|---|---|---|---|---|
| `RECEIVED` | 예약 접수 | 접수 | 파랑 | `#1F5BD6` / `#EAF1FF` | 5.3 | `.ac-badge--received` |
| `ASSIGN_WAIT` | 기사 배정 중 | 미지정(긴급) | 주황 | `#B54708` / `#FFF1E6` | 4.9 | `.ac-badge--assign-wait` |
| `ASSIGNED` | 기사 배정 완료 | 배정완료 | 남색 | `#2B3A8F` / `#E9ECF8` | 8.5 | `.ac-badge--assigned` |
| `ON_THE_WAY` | 기사님 이동 중 | 이동중 | 보라 | `#6A3DC2` / `#F2EDFD` | 6.0 | `.ac-badge--on-the-way` |
| `IN_PROGRESS` | 작업 중 | 작업중 | 청록 | `#0A7470` / `#E2F5F4` | 5.0 | `.ac-badge--in-progress` |
| `PENDING` | 일정 조율 중 | 미처리 | 빨강 | `#C02626` / `#FDECEC` | 5.2 | `.ac-badge--pending` |
| `PENDING` (48h 경과) | 일정 조율 중 | 미처리 | **진한 빨강 채움** | `#FFFFFF` / `#A51C1C` | 7.6 | `.ac-badge--pending-overdue` |
| `WORK_DONE` | 작업 완료(결제 대기) | 작업완료 | 연두 | `#3F7313` / `#EDF7E2` | 5.2 | `.ac-badge--work-done` |
| `COMPLETED` | 완료 | 완료 | 회색 | `#4A515C` / `#EDEFF2` | 7.0 | `.ac-badge--completed` |
| `CANCELED` | 취소 | 취소 | 연회색 + 테두리 | `#646B78` / `#F5F6F8` | 4.9 | `.ac-badge--canceled` |

**규칙**

- 형태: 알약형, 높이 26px(관리자 22px, 상세 화면 `--lg` 32px), 좌측 6px 점, 12px/600.
- `ON_THE_WAY`, `IN_PROGRESS`는 점이 천천히 깜박여 "진행 중"을 표현합니다(`prefers-reduced-motion` 시 정지).
- `PENDING` 48시간 경과는 배경을 채운 반전형으로 바꿔 목록에서 즉시 눈에 띄게 합니다. 경과 판단은 서버/앱 로직에서 클래스만 바꿉니다.
- `COMPLETED`는 목록 하단 정렬. 관리자 그리드에서 강조가 필요하면 행에 `.is-highlight`(노란 배경)를 적용합니다.
- `CANCELED`는 행 전체를 `.is-muted`로 흐리게 처리할 수 있습니다.
- 코드에서는 `tokens.json`의 `status` 맵(`labelCustomer`, `labelStaff`, `className`)을 그대로 불러 쓰면 3채널 표시가 어긋나지 않습니다.

**보조 태그**(사각형 4px 반경, 상태와 구분): `마감`(danger), `할증`(warning), `추천`(primary), `보증`(success), `필수`(기본). 알림 숫자는 `.ac-count`(빨강 원형).

## 3. 타이포그래피

### 3.1 폰트

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/orioncactus/pretendard@v1.3.9/dist/web/variable/pretendardvariable-dynamic-subset.min.css">
```

```css
--font-sans: "Pretendard Variable", Pretendard, -apple-system, BlinkMacSystemFont, system-ui,
             "Apple SD Gothic Neo", "Noto Sans KR", "Malgun Gothic", "Segoe UI", Roboto, sans-serif;
```

- 라이선스: SIL Open Font License 1.1 (상업적 사용·임베딩 무료). 운영 시에는 CDN 대신 자체 호스팅을 권장합니다.
- `word-break: keep-all`로 한글을 단어 단위로 줄바꿈합니다.
- 금액·시간·건수·접수번호에는 `.ac-num`(`font-variant-numeric: tabular-nums`)을 적용해 숫자 폭을 고정합니다.

### 3.2 타입 스케일

| 토큰 | 모바일 | md(768+) | xl(1280+) | 행간 | 굵기 | 용도 |
|---|---|---|---|---|---|---|
| `display` | 32 | 40 | 48 | 1.3 | 700 | 랜딩 히어로 |
| `h1` | 26 | 30 | 34 | 1.35 | 700 | 페이지 제목 |
| `h2` | 22 | 24 | 26 | 1.4 | 700 | 섹션 제목 |
| `h3` | 19 | 20 | 20 | 1.45 | 600 | 카드 묶음 제목 |
| `title` | 17 | 17 | 17 | 1.5 | 600 | 카드 제목, 목록 제목 |
| `body-lg` | 17 | 17 | 17 | 1.6 | 400 | 강조 본문 |
| `body` | 15 | 15 | 15 | 1.6 | 400 | 기본 본문 |
| `body-sm` | 14 | 14 | 14 | 1.55 | 400 | 보조 본문 |

| `micro` | 12 | 12 | 12 | 1.45 | 400~600 | 배지, VAT 표기 |

- 채널 보정: 기사 앱은 body 16 / body-sm 15 / caption 14, 관리자는 body 14 / body-sm 13 / caption 12, h1~h3은 22/18/16.
- 자간: 제목 `-0.02em`, 본문 `-0.01em`.
- 최소 글자 크기 12px. 11px은 하단 탭 라벨에만 허용합니다.

| 토큰 | 값 | 용도 |
|---|---|---|
| `--shadow-xs` | `0 1px 2px rgba(20,28,40,.05)` | 미세 구분 |
| `--shadow-sm` | `0 2px 8px …/.06` | 세그먼트 선택, 스위치 노브 |
| `--shadow-md` | `0 6px 20px …/.08` | 강조 카드, 카드 hover |
| `--shadow-lg` | `0 12px 32px …/.12` | 토스트, 드롭다운 |
| `--shadow-xl` | `0 20px 48px …/.16` | 모달, 바텀시트 |
| `--shadow-fixed-bottom` | `0 -4px 16px …/.06` | 하단 고정 바 |

기본 카드는 그림자 없이 1px 테두리. 그림자는 "떠 있는" 요소에만 씁니다.

### 5.3 모션

| 토큰 | 값 | 용도 |
|---|---|---|
| `--duration-fast` | 120ms | hover, 색 전환 |
| `--duration-base` | 200ms | 토글, 탭 |
| `--duration-slow` | 320ms | 시트·모달 진입, 진행바 |
| `--ease-standard` | `cubic-bezier(.2,0,0,1)` | 기본 |

`prefers-reduced-motion: reduce`에서는 모든 duration이 0이 됩니다. 버튼은 누를 때 `scale(0.98)`.

## 6. 컴포넌트 규칙

클래스는 `ac-` 접두사. 프레임워크와 무관하게 `components.css`만 불러오면 동작하며, React/Vue 컴포넌트로 옮길 때도 같은 이름·속성을 유지합니다.

### 6.1 버튼 `.ac-btn`

| 변형 | 클래스 | 사용처 |
|---|---|---|
| Primary | `--primary` | 화면의 핵심 행동 1개 (견적 받기, 예약하기, 저장, 조회) |
| Secondary | `--secondary` | 보조 행동 (저장·공유, 상세 보기, 전화 접수) |
| Outline | `--outline` | 중립 행동 (일정 변경, 취소, 거절, 엑셀 다운로드) |
| Ghost | `--ghost` | 낮은 우선순위 (초기화, 닫기) |
| Dark | `--dark` | 블루가 과할 때의 강조 (기사 "출발하기", 배너 위 버튼) |
| Danger | `--danger` | 되돌릴 수 없는 행동 (예약 취소, 삭제), 확인 모달 안에서만 |
| Text | `--text` | 인라인 링크형 (약관 보기, 전체 ›) |

| 크기 | 고객 | 기사 | 관리자 | 클래스 |
|---|---|---|---|---|
| sm | 36 | 44 | 28 | `--sm` |
| md(기본) | 44 | 52 | 36 | – |
| lg | 52 | 56 | 40 | `--lg` |
| xl | 56 | 64 | 44 | `--xl` |

- 형태: 알약형, 좌우 패딩 = 높이의 50%, 15px/600. 아이콘 버튼은 정사각(`--icon`) + `aria-label` 필수.
- 상태: hover(한 단계 진하게) / pressed(두 단계 + scale .98) / focus(`--focus-ring`) / loading(`.ac-spinner` + 문구 "결제 중") / disabled(gray-100 배경, gray-400 글자).
- 모바일 하단 버튼 2개: 보조(outline) : 주(primary) = **1 : 2** 폭, 주 버튼은 오른쪽.
- 모바일 단일 CTA는 `--block --xl`로 화면 폭 전체.
- 필수 사진 미촬영 등 조건 미충족 시 다음 단계 버튼은 `disabled`(03_IA §6.2 기사 앱 규칙).

### 6.2 입력 `.ac-field` / `.ac-input` / `.ac-select` / `.ac-textarea`

- 높이: 고객 48 · 기사 52 · 관리자 36. 반경 12(관리자 8). 테두리 gray-300, hover gray-400, focus blue-600 + focus ring.
- 라벨은 **항상 입력 위**(플레이스홀더를 라벨로 쓰지 않음). 필수는 라벨 뒤 빨간 `*`(`.ac-req`).
- 도움말·오류는 입력 아래 13px. 오류 시 `.ac-field--error` 또는 `aria-invalid="true"` → 빨간 테두리 + 빨간 문구.
- 오류 문구 형식: **"○○은(는) 필수 입력값입니다."** (03_IA §6.2 관리자 규칙, 고객·기사도 동일 형식 사용)
- 읽기 전용은 gray-50 배경(`readonly`). 비활성은 gray-50 배경 + gray-400 글자.
- 관리자 검색 영역(`.ac-search-panel`)에서 **Enter = 조회**. 조회 버튼은 우측 끝 primary.
- 휴대폰·숫자 입력은 `inputmode="tel" | "numeric"`.

**선택 컨트롤**

| 컴포넌트 | 클래스 | 규칙 |
|---|---|---|
| 체크박스 | `.ac-check > input[type=checkbox]` | 22px, 반경 6, 선택 시 blue 채움 + 흰 체크. 약관은 "전체 동의" 굵게 맨 위 |
| 라디오 | `.ac-check > input[type=radio]` | 22px 원형, 선택 시 blue + 흰 링 |
| 스위치 | `.ac-switch > input` | 48×28, 즉시 반영되는 설정(알림·위치 동의)에만 |
| 스테퍼 | `.ac-stepper` | 알약형, − / 수량 / +. 최솟값에서 − 비활성 (기기 대수) |
| 선택 카드 | `.ac-card--interactive` + `--selected` | 기기 형태처럼 그림이 있는 선택지. 선택 시 blue 2px 테두리 + blue-50 배경, `aria-pressed` |

행 전체가 터치 영역이 되도록 `min-height: var(--touch-min)`을 보장합니다.

### 6.3 카드 `.ac-card`

| 변형 | 클래스 | 사용처 |
|---|---|---|
| 기본 | – | 예약 카드, 작업 카드: 1px gray-200 테두리, 그림자 없음 |
| 강조 | `--elevated` | 정산 요약, 대시보드 KPI: 테두리 없이 shadow-md |
| 면 | `--subtle` | 내 기기, 안내 박스: gray-50 면 |
| 클릭형 | `--interactive` | hover 시 shadow-md |
| 선택됨 | `--selected` | 선택 카드 |

- 반경 20(관리자 12), 패딩 20(md+ 24, 관리자 16×20).
- 구성: `__header`(상태 배지 좌 · 날짜/시간 우) → 제목(title) → 메타(caption) → `__footer`(구분선 + 버튼).
- **예약·작업 카드는 상태 배지를 항상 좌상단**에 둡니다. 3채널에서 위치가 같아야 학습 비용이 줄어듭니다.

### 6.4 내비게이션

| 컴포넌트 | 클래스 | 규칙 |
|---|---|---|
| 하단 탭바 | `.ac-tabbar` | 고객 4탭, 기사 5탭(03_IA §2.1, §3.1). 아이콘 24 + 라벨 11. 현재 탭은 gray-900 굵게(블루 아님). 스텝 플로우에서는 숨김 |
| 상단 탭 | `.ac-tabs` / `.ac-tab` | 목록 상태 분류(진행/완료/취소). 선택 탭은 검정 2px 밑줄 |
| 세그먼트 | `.ac-segmented` | 같은 데이터의 보기 전환(목록 ⇄ 지도, 근무 ⇄ 메모) |

### 6.5 하단 고정 바 `.ac-bottom-bar`

- 고객 앱 스텝 플로우·견적 결과·결제에서 **금액은 항상 하단 고정 바에 표시**(03_IA §6.2).
- 좌: 라벨(caption) + 금액(h3, 700, tabular-nums, 줄바꿈 금지) / 우: primary lg 버튼(최소 128px).
- 상단에 `--shadow-fixed-bottom`, 하단에 `env(safe-area-inset-bottom)` 여백.

### 6.6 피드백

| 상황 | 컴포넌트 | 문구·규칙 |
|---|---|---|
| 저장 전 확인 | `.ac-modal` (Confirm) | "저장하시겠습니까?" + 영향 설명 1줄. [취소 outline][저장 primary] |
| 저장 성공 | `.ac-toast` (Notification) | "저장에 성공하였습니다." 하단 중앙, 3초 후 사라짐 |
| 필수 누락 | 필드 오류 + 첫 오류 필드로 포커스 | "○○은(는) 필수 입력값입니다." |
| 안내·경고 | `.ac-alert` (`--success` `--warning` `--danger`) | 아이콘 + 1~2줄. 추가요금 가능성은 견적 단계에서 info 알림으로 미리 공개 |
| 바텀시트 | `.ac-sheet` | 모바일 변경·취소, 증빙 신청 등 (03_IA 유형 B). 상단 핸들, 반경 28 |
| 진행 중 작업 | `.ac-live-banner` | 기사 앱 모든 화면 상단 고정, 다크 배경 + [이어하기] |
| 오프라인 | `.ac-offline` | warning 색 점 + "오프라인 저장됨" |
| 빈 상태 | `.ac-empty` | "조회 결과가 없습니다." + 회색 아이콘 48 |
| 로딩 | `.ac-skeleton` / `.ac-spinner` | 목록·카드는 스켈레톤, 버튼은 스피너 |

- 파괴적 행동(예약 취소·삭제)은 Confirm 모달 안에서만 danger 버튼을 씁니다.
- 브라우저 기본 `alert()`·`confirm()`은 쓰지 않고 위 컴포넌트로 통일합니다.

### 6.7 데이터 표 (관리자) `.ac-table`

- 헤더 40px(gray-50, 600), 행 44px, 본문 13~14px, 줄바꿈 없음 + 가로 스크롤(`.ac-table-wrap`).
- 숫자·금액 열은 `.is-num`(우측 정렬, tabular-nums). 날짜·접수번호도 `.ac-num`.
- hover = blue-50, 선택 행 `.is-selected` = blue-100, 강조 행 `.is-highlight` = 노랑, 비활성 행 `.is-muted`.
- **더블클릭 = 상세/로드**(03_IA §6.2). 헤더는 sticky.
- 결과 수("총 128건")는 표 좌상단, 일괄 버튼(엑셀 등)은 우상단 sm 크기.

### 6.8 개인정보 마스킹 `.ac-masked`

- 목록에서는 `010-****-1234`처럼 마스킹하고 옆에 작은 [보기] 버튼.
- [보기] 클릭 시 원문 표시 + 감사 로그 기록(03_IA §6.2). 버튼은 권한이 있는 역할에만 렌더링합니다.

## 8. 코드 사용법

### 8.1 파일 구성

```
aircon-platform-docs/
├── 05_디자인시스템.md               ← 이 문서
├── 05_디자인시스템_미리보기.html    ← 단일 파일 미리보기 (CSS 내장)
└── design-system/
    ├── tokens.css        ← CSS 변수 (원시·의미·상태·타이포·간격·반경·그림자·채널 밀도)
    ├── components.css    ← ac- 컴포넌트 클래스 (tokens.css 다음에 로드)
    └── tokens.json       ← 같은 값의 JSON (상태 코드 → 표시명·클래스 맵 포함)
```

### 8.2 HTML 적용

```html
<html lang="ko" data-channel="customer">  <!-- tech | admin -->
<head>
  <link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/orioncactus/pretendard@v1.3.9/dist/web/variable/pretendardvariable-dynamic-subset.min.css">
  <link rel="stylesheet" href="/design-system/tokens.css">
  <link rel="stylesheet" href="/design-system/components.css">
</head>
<body>
  <span class="ac-badge ac-badge--on-the-way">기사님 이동 중</span>
  <button class="ac-btn ac-btn--primary ac-btn--xl ac-btn--block">견적 받기</button>
</body>
```

### 8.3 상태 배지 헬퍼 (예시)

```js
import tokens from './design-system/tokens.json';

// channel: 'customer' | 'staff'
export function statusBadge(code, channel, { overdue48h = false } = {}) {
  const s = tokens.status[code];
  const cls = overdue48h && s.overdue48h ? s.overdue48h.className : s.className;
  const label = channel === 'customer' ? s.labelCustomer : s.labelStaff;
  return `<span class="ac-badge ${cls}">${label}</span>`;
}
```

### 8.4 Tailwind를 쓸 경우

`tailwind.config`의 `theme.extend`에서 CSS 변수를 참조하면 토큰이 한 곳에서 관리됩니다.

```js
colors: {
  primary: { DEFAULT: 'var(--color-primary)', hover: 'var(--color-primary-hover)', subtle: 'var(--color-primary-subtle)' },
  fg: { DEFAULT: 'var(--color-text)', secondary: 'var(--color-text-secondary)', tertiary: 'var(--color-text-tertiary)' },
},
borderRadius: { card: 'var(--radius-card)', input: 'var(--radius-input)', full: '9999px' },
screens: { sm: '360px', md: '768px', lg: '1024px', xl: '1280px', '2xl': '1440px' },
fontFamily: { sans: ['Pretendard Variable', 'Pretendard', 'system-ui', 'sans-serif'] },
```

### 8.5 기사 앱이 네이티브(React Native/Flutter)일 경우

`tokens.json`을 그대로 불러 색·간격·반경 상수로 씁니다. 48dp 기준은 `channelOverrides.tech` 값을 따릅니다.
