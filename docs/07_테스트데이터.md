# 07. 테스트용 가상 데이터

고객 웹 · 상담 콘솔 · 기사 웹앱 · 관리자 웹의 기능을 손으로 눌러 보며 확인할 수 있도록, **모든 채널에 걸친 가상 데이터**를 넣는 시드입니다.

- 코드: `packages/db/src/seed-demo.ts`(넣는 순서·시나리오), `packages/db/src/seed-demo-fixtures.ts`(계정·상품·단가 등 고정값), `packages/db/scripts/seed-demo.ts`(실행 진입점)
- 모든 이름·연락처·주소는 **가상 값**입니다. 휴대폰은 `010-0000-xxxx`, 이메일은 `@example.com`, 주소는 실제 동 코드에 가상 번지를 붙였습니다.
- 가상 데이터 행은 주문 `internal_note`, 메모·공지 등에 `[가상 데이터]` 표시가 붙습니다.
- **운영 DB에는 넣지 마세요.** 오픈 전 테스트용 Supabase 프로젝트나 로컬 DB에서만 씁니다.

## 1. 넣는 방법

### 1.1 GitHub 화면에서 (권장)

1. 저장소 **Settings > Secrets and variables > Actions**에 아래 Secret을 추가합니다. (기존 `DATABASE_URL`·`SUPABASE_*`·`SEED_SUPER_ADMIN_*`는 그대로 둡니다.)

   | Secret | 값 |
   |---|---|
   | `PII_ENCRYPTION_KEY` | **Vercel 환경변수와 같은 값** (32바이트 base64). 다르면 화면에서 이름·연락처가 깨지고 휴대폰 번호 로그인이 안 됩니다. |
   | `PII_HASH_PEPPER` | **Vercel 환경변수와 같은 값** |
   | `SEED_DEMO_PASSWORD` | 테스트 관리자·기사 계정 공통 비밀번호(8자 이상, 직접 정함). 없으면 `SEED_SUPER_ADMIN_PASSWORD`를 씁니다. |

2. **Actions > "DB 준비 (마이그레이션·시드)" > Run workflow**에서 `기본 데이터` ✅, `테스트용 가상 데이터` ✅ 를 켜고 실행합니다. **가상 데이터 체크박스는 기본값이 꺼짐**이라 직접 켜야 합니다.
   - 끝나면 로그의 "테스트용 가상 데이터 넣기" 단계 마지막 줄에 `테스트 데이터 완료: 관리자 +8, 기사 +8, 고객 +12, 주문 +47 …`이 나옵니다. 이 단계가 skipped 면 데이터가 들어가지 않은 것입니다.
   - 관리자 인증 계정은 Supabase Auth에, 작업 사진 예시 이미지는 Supabase Storage(`attachments` 버킷)에 올라갑니다.

### 1.2 로컬에서

```bash
pnpm build --filter "./packages/*"
pnpm db:migrate && pnpm db:seed          # 기본 데이터 먼저
SEED_DEMO_PASSWORD=... pnpm db:seed:demo # DATABASE_URL·PII_ENCRYPTION_KEY·PII_HASH_PEPPER 도 필요
```

`AUTH_DRIVER=mock`이면 관리자 계정이 로컬 mock 인증에 만들어지고(이때 `SESSION_SECRET` 16자 이상 필요), `STORAGE_DRIVER=mock`이면 예시 이미지가 `STORAGE_LOCAL_DIR`에 저장됩니다.

### 문제가 생기면: 먼저 설정 점검 주소를 열어 보세요

브라우저로 `https://<배포 주소>/api/health` 를 열면 운영 서버의 설정 상태가 나옵니다(값·개인정보는 나오지 않음).

| 항목 | 정상 | 아닐 때 할 일 |
|---|---|---|
| `database` | `ok` | `missing`: Vercel에 `DATABASE_URL`이 없음. `error`: 연결 실패(`databaseErrorCode` 참고, 예: `28P01` 비밀번호 틀림, `ENOTFOUND` 주소 틀림, `XX000` Pooler 사용자명 틀림). Vercel `DATABASE_URL`을 Supabase > Connect > Transaction pooler 문자열로 다시 넣고 Redeploy |
| `piiKey` | `ok` | `missing`/`invalid`: 아래 "암호화 키" 절차 |
| `piiDecryptFail` | `0` | 1 이상이면 Vercel 키와 데이터를 넣은 키가 다름: 아래 "암호화 키" 절차 |
| `piiHashPepper` | `set` | Vercel에 `PII_HASH_PEPPER` 추가 |

DB에 연결하지 못하면 고객 주소 검색 등 저장·조회 화면에 `서버 설정 오류: 데이터베이스에 연결하지 못했습니다(DATABASE_URL 확인, 코드 …)`가 뜹니다.

### 문제가 생기면: 화면에 "Application error"가 나오거나 이름·연락처가 비어 보일 때 (암호화 키)

가상 데이터를 넣을 때 쓴 `PII_ENCRYPTION_KEY`(GitHub Secret)와 앱이 쓰는 값(Vercel)이 다르거나, Vercel 값의 형식이 틀리면(32바이트 base64가 아님) 앱이 이름·연락처·주소를 풀지 못합니다. 화면은 깨지지 않고 해당 칸이 비어 보이며, Vercel 로그에 `[PII] 복호화 실패` 또는 `[PII] 복호화 건너뜀`이 남습니다. 형식이 틀리면 고객 휴대폰 인증·저장 화면에 `서버 설정 오류: PII_ENCRYPTION_KEY는 32바이트 base64 값이어야 합니다`가 뜹니다.

값 앞뒤의 공백·줄바꿈, 감싼 따옴표(`"…"`), `PII_ENCRYPTION_KEY=` 접두어는 앱과 시드가 자동으로 걷어 냅니다.

가장 확실한 복구 방법은 **새 키 하나를 두 곳에 똑같이 넣는 것**입니다(GitHub Secret은 값을 다시 볼 수 없기 때문).

1. 새 키를 만듭니다: `openssl rand -base64 32` (끝이 `=`인 44자). 터미널이 없으면 기존 Vercel 값이 44자 base64로 정상인지 확인해 그 값을 씁니다.
2. Vercel > 프로젝트 > Settings > Environment Variables의 `PII_ENCRYPTION_KEY`(Production·Preview)를 그 값으로 바꾸고, Deployments에서 최신 배포를 **Redeploy** 합니다. 환경변수는 다시 배포해야 반영됩니다.
3. GitHub 저장소 Settings > Secrets and variables > Actions의 `PII_ENCRYPTION_KEY`를 같은 값으로 바꿉니다(`PII_HASH_PEPPER`는 이미 로그인이 되면 맞는 값입니다).
4. "DB 준비"를 `테스트용 가상 데이터` ✅ 로 다시 실행합니다. 새 키로 풀리지 않는 가상 데이터를 원래 값으로 다시 암호화합니다(로그: `암호화 복구: … N건`). 가상 데이터가 아닌, 직접 입력한 개인정보는 예전 키로만 풀리므로 다시 입력해야 합니다.

"DB 준비"는 한 번에 하나만 실행됩니다. 앞 실행이 끝날 때까지(가상 데이터는 10분쯤 걸림) 다음 실행은 기다립니다.

### 1.3 다시 실행하면

- 지점·상품·계정·고객 같은 기준 데이터는 **없는 것만** 넣습니다(코드·로그인 ID·전화번호 해시로 확인).
- 시드 전에 테스트 번호로 먼저 로그인해 고객이 생겼어도, 그 고객에 예시 주소와 이력이 붙습니다(등급·태그는 바뀌지 않음).
- **지난 이력**(최근 5주 완료 주문·정산·상담·VOC·캠페인·교육 등)은 처음 한 번만 넣습니다.
- **오늘 일정**(오늘 작업·코스·다가오는 예약)은 **날짜(KST)마다 한 번** 넣습니다. 며칠 뒤 다시 실행하면 그날 기준의 새 "오늘" 묶음이 생깁니다. 일요일에 실행하면 월요일 기준으로 넣습니다.
- 각 묶음은 트랜잭션으로 넣어, 중간에 실패하면 그 묶음 전체가 들어가지 않습니다.

## 2. 로그인 방법

| 채널 | 주소 | 방법 |
|---|---|---|
| 관리자 · 상담 콘솔 | `/admin/login` | 아래 **로그인 ID** + `SEED_DEMO_PASSWORD` |
| 기사 | `/tech/login` | **비밀번호** 탭: 휴대폰 번호 + `SEED_DEMO_PASSWORD`<br>또는 인증번호 탭(`IDENTITY_DRIVER=mock`일 때 화면에 인증번호 표시) |
| 고객 | `/login` → 휴대폰 로그인 | 이름 + 휴대폰 번호 → 인증번호(`IDENTITY_DRIVER=mock`이면 화면에 표시, `IDENTITY_MOCK_AUTO_VERIFY=true`면 입력 생략) |

> 고객·기사 인증번호 로그인은 Vercel에 `IDENTITY_DRIVER=mock`이 설정돼 있어야 합니다. 실제 본인인증(PortOne)으로 바꾼 뒤에는 가상 번호로 인증할 수 없으니, 기사는 비밀번호 탭을 쓰세요.
